# MNYRA Full Role Permission Matrix

Status: CURRENT
Generated: 2026-07-01
Branch: `mnyrasocial`

## Scope

This matrix summarizes current effective permissions from `firestore.rules`,
the tested Function order flow, app controllers and Heart/waiter code. It is an
audit document, not a rules change.

## Roles

| Role               | Current meaning                                                                                                       |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Guest              | Not signed in. Can read public business/profile/menu/feed surfaces.                                                   |
| Signed-in user     | Normal authenticated user with own user profile, favorites, notifications, devices and orders.                        |
| Buyer              | Signed-in or guest order customer. Guest recovery uses order lookup token; signed-in mirrors use own user order docs. |
| Business owner     | User that owns or manages a restaurant/business document.                                                             |
| Restaurant owner   | Business owner using restaurant/cafe/bar menu, QR and order tools.                                                    |
| Shop/grocery owner | Business owner using product/menu infrastructure for products.                                                        |
| Hotel/travel owner | Business owner using focus/offers fields for travel/hotel offers.                                                     |
| Staff              | Business staff account represented under restaurant staff documents or user managed staff state.                      |
| Waiter             | Staff role with restaurant order read/status permissions.                                                             |
| CEO                | Global admin actor for leads, CRM/admin, broad owner/customer/staff operations and privileged rules.                  |
| Heart/Admin        | Heart/CRM admin UI and handlers, backed by CEO/admin identity checks and shared adapters.                             |

## Operation Matrix

| Operation                       | Current allowed actor                                              | Notes                                                                           |
| ------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| Create restaurant order         | Callable Function only                                             | Browser create is denied for guests and signed-in users.                        |
| Compute order totals            | Server Function                                                    | Function reads trusted menu items and ignores client total/status/buyer fields. |
| Read own signed-in order mirror | Buyer user                                                         | `users/{uid}/orders` is self-readable only.                                     |
| Recover guest order             | Guest with lookup token                                            | `orderLookup/{token}` get is public; listing is restricted.                     |
| Update order status             | Authorized restaurant actor                                        | Waiter/owner/CEO only, status/timestamp-only shape.                             |
| Manage menu items               | Owner/business staff/CEO                                           | Public readable.                                                                |
| Publish public menu             | Owner/business staff/CEO                                           | Browser owner path writes public menu doc.                                      |
| Configure table QR              | Owner/business staff/CEO                                           | Stored in public meta.                                                          |
| Create owner ad                 | Owner/business actor                                               | Saved as pending ad item under public ads doc.                                  |
| Approve/reject ad               | Heart/CEO                                                          | Mutates ad item status in public ads doc.                                       |
| Save lead                       | CEO/Heart                                                          | Writes lead and can update/create linked restaurant/account state.              |
| Read CRM customers              | CEO/Heart scoped loaders                                           | Derived from `restaurants`, leads and staff/admin collections.                  |
| Write user privileged fields    | Self with protected fields blocked, CEO/admin for privileged paths | Rules protect role/counter/privileged fields.                                   |

## Required Permission Work Before Enterprise Launch

1. Replace broad public `restaurants` read dependency with explicit public
   projection documents or field allowlists.
2. Freeze public personal profile visibility states before exposing public user
   profile routes.
3. Split ads into per-ad documents or add strict item-level audit/history
   semantics.
4. Add analytics event write/read rules before collecting production metrics.
5. Add revocation tests for staff/waiter/owner role changes.
6. Add conversion tests for lead-to-owner-account and restaurant provisioning.
7. Add matrix-driven rules tests for every role and collection in this file.
