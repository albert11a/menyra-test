# Creator video sales and silent looping previews

User request 2026-10-31: select and sell video files in Content Creator packages;
preview them like feed story tiles: muted, inline, looping, no play/volume controls.
Keep original downloads behind the existing free/purchased ownership checks.
Use persistent Creator storage, not expiring public story uploads. No feed changes,
Firestore rules, external services, new dependencies or production-data tests.

## Implementation

- Shop package creation, existing package additions and shop creation accept
  MP4/MOV/WebM alongside JPG/PNG/WebP. Existing image-only promo/avatar flows
  remain image-only. Current limits: 30 MB per original, 60 seconds per video.
- Existing private original chunks preserve the uploaded file, filename and
  audio byte for byte. A lazy-loaded browser canvas encoder makes a separate
  silent, 480 px / 20 fps preview, capped at 4 MB. Paid previews use the existing
  20% watermark painter on every frame. No paid clean video is uploaded to R2.
- The existing CDN image uploader serves only a still poster. Public manifests
  expose media type and poster variants, never original paths/bytes. Video
  preview data is private under an immutable generation of the original.
- A read-only video endpoint checks the published page and active package,
  selects the correct marked/free preview, and supports bounded Range and HEAD
  responses. Invalid/incomplete previews never fall back to original bytes.
- Visible current cards and the viewer run muted/inline/loop with no native
  controls. Offscreen, covered and background previews pause; the playing
  node survives cart rerenders. Video originals are not automatically prefetched
  just because a save button enters the viewport.
- Free and purchased originals use the existing download gates and share flow,
  with video/mixed-package counts and video-aware download labels. Business
  deletion also cleans preview generations from interrupted uploads.
- No new dependency, paid service, Worker/Rules deployment or feed modification.

## Verification

- 127 focused Creator, upload, server/HTTP, DOM, deletion and Pixel guard tests
  passed. Includes mixed photo/video additions, no public original upload,
  failed encoding, preview ranges, HEAD, unpublished/private access denial,
  original MOV bytes/MIME, paid checkout/download and video node retention.
- npm run build passed after final source changes. Tracked Social bundles did
  not change; ignored dist entries are regenerated by the build.
- Manual cloud-browser verification with a local synthetic two-second MP4:
  actual canvas encoder produced a 56,236-byte MP4 preview, displayed its
  watermark, and played it silently in a loop with controls=false. No camera,
  microphone, customer video, production write or actual purchase was used.
- Existing phone-sized layout is retained; CSS keeps video in the same card,
  viewer and thumbnail bounds. No real iPhone/Safari or Android upload was
  performed. Browser/OS autoplay restrictions may leave the poster visible.
- No Playwright/smoke suite or full repository suite; focused regression tests
  and production build cover this change. git diff --check passed.

## Manual phone check after release

Refresh Heart, open a shop, create a package or add to an existing one, select a
short MP4/MOV, set title/price and keep Heart open until upload completes. Open
Still preview: visible video loops silently without controls; scroll away and
back, then check the large viewer and cart. A purchased original must retain
sound and original resolution. Existing photos must keep their current behavior.

Payload comparison with identical minified esbuild/gzip settings: Creator entry
16,051 -> 17,265 bytes, stylesheet 5,843 -> 5,996 bytes. Video loading is lazy;
this comparison does not claim identical timing on real mobile networks.
